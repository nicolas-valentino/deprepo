# Política editorial

El ciclo es capturar → extraer → relacionar → contrastar → sintetizar → aplicar. Cada documento debe cambiar una decisión, explicar un fenómeno o formular una pregunta comprobable.

## Afirmaciones y procedencia

La evidencia se registra por entrada y se distingue dentro del cuerpo. `mixed` no debe esconder incertidumbre: el lector tiene que poder ubicar qué proviene de documentación, qué se reportó y qué inferimos. Los relatos de DepreIA se citan como síntesis privada, sin personas, citas ni identificadores de mensajes.

Una herramienta oficial queda verificada en identidad y alcance documentado; no por ello se considera auditada ni recomendada. Las fichas tienen prueba de decisión y alternativa. No se publican precios, cuotas, políticas de datos o nombres de versiones copiados del chat sin contraste actual.

En investigación, consultar el abstract permite verificar tema y afirmaciones de los autores, pero no equivale a replicar ni revisar todo el artículo. Esta edición hace síntesis de alcance; sus fuentes primarias no fueron reproducidas experimentalmente. Un resultado de fine-tuning no se convierte en resultado sobre pretraining. Un modelo teórico no se presenta como medición causal.

## Contradicciones que se conservan

| Discusión | Resolución editorial |
| --- | --- |
| Harness como aplicación o personalización | Definición operativa de la capa alrededor del modelo; se conserva el desacuerdo terminológico |
| Vault personal y memoria del agente juntos o separados | Dos diseños con costos diferentes; decidir por inspección, corrección y mantenimiento |
| Sistema de triage complejo | Registrar propuesta inicial y posterior simplificación; conservar convenciones que sí funcionaron |
| Mejor modelo como solución a alignment | Evaluar capacidad y restricciones por separado; no declarar resuelta la discusión |
| Progreso tecnológico como bienestar | Separar calidad, precio, distribución y acceso; no inferir macroeconomía de un ejemplo |
| Representaciones emocionales como conciencia | Diferenciar función de experiencia subjetiva |

## Publicación y revisión

Las propuestas se revisan por PR. Revisar el diff staged completo, fuentes, enlaces y cambios de recomendación. No subir originales, siquiera en un commit luego borrado. Usar crudos solo fuera del checkout y compartir agregados tras revisión.

Las fechas de revisión son orientativas. Marcar como experimental o deprecated si la evidencia cambia, conservando una explicación de por qué. Un enlace caído no invalida automáticamente un resultado; buscar la fuente original o una copia autorizada.
